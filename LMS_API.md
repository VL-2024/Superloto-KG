# ЧҮКӨ — обмен игры с LMS (v20)

## 1. Общая схема

В реальном режиме LMS является источником истины для денежных операций и результата билета.

Последовательность:

1. LMS запускает игру и передаёт ей стартовые параметры.
2. Игрок выбирает доступный номинал билета внутри игры.
3. При запуске раунда игра вызывает `PayTicket`.
4. LMS списывает стоимость билета, определяет результат и возвращает данные билета.
5. Игра только визуализирует полученный результат и показывает новый баланс.

Игра не рассчитывает реальный выигрыш самостоятельно.

---

## 2. Покупка билета / запуск реального раунда

Формат запроса, переданный разработчиком LMS:

```http
GET https://dev.superloto.kg/api/Lotto.Users.cls?Method=PayTicket&gameId=137&amount=15
```

### Параметры запроса PayTicket

| Параметр | Тип | Обязательный | Кто задаёт | Описание |
|---|---|---:|---|---|
| `Method` | string | да | игра | Имя вызываемого метода LMS. Для покупки билета всегда `PayTicket`. |
| `gameId` | integer/string | да | LMS | ID конкретной игры в LMS. Передаётся игре при запуске. В код игры конкретное значение не зашивается. Например: `137`. |
| `amount` | number | да | игрок / игра | Фактически выбранный игроком номинал билета на текущий раунд. Например: `15`, `30`, `50`. Игра подставляет выбранное значение в запрос `PayTicket`. |

Пример: игрок выбрал билет за 30 сом:

```http
GET https://dev.superloto.kg/api/Lotto.Users.cls?Method=PayTicket&gameId=137&amount=30
```

## 3. Ответ LMS на PayTicket

Минимальный ответ, необходимый игре:

```json
{
  "ticketId": "123456789",
  "scenario": 3,
  "win": 30,
  "balance": 1240
}
```

Расширенный вариант:

```json
{
  "ticketId": "123456789",
  "scenario": 3,
  "win": 30,
  "balance": 1240,
  "denomination": 15,
  "currency": "KGS",
  "currencyDisplay": "сом",
  "multiplier": 2
}
```

### Параметры ответа PayTicket

| Параметр | Тип | Обязательный | Описание |
|---|---|---:|---|
| `ticketId` | string/integer | да | Уникальный ID или номер созданного билета в LMS. Нужен для идентификации конкретной игровой операции. |
| `scenario` | integer | да | Номер визуального сценария результата в игре. Для ЧҮКӨ допустимы значения `1..5`. |
| `win` | number | да | Сумма выигрыша по этому билету в валюте игрока. При проигрыше — `0`. |
| `balance` | number | да | Актуальный реальный баланс игрока после завершения операции по билету. Игра показывает именно это значение, а не рассчитывает баланс сама. |
| `denomination` | number | нет | Номинал/стоимость данного билета. Обычно совпадает с `amount`, который игра отправила в `PayTicket`. Может возвращаться для дополнительного контроля. |
| `currency` | string | нет | Код валюты, например `KGS`, `RUB`. Валюта задаётся LMS; игрок её внутри игры не меняет. |
| `currencyDisplay` | string | нет | Текстовое обозначение валюты для интерфейса: например `сом`, `₽`, `$`. |
| `multiplier` | number | нет | Множитель выигрыша для отображения в интерфейсе. Если не передан, игра может вычислить его для отображения как `win / denomination`. На денежный расчёт это не влияет. |

### Сценарии ЧҮКӨ

| `scenario` | Результат анимации |
|---:|---|
| `1` | ничего не выбито |
| `2` | выбито 1 чүкө |
| `3` | выбито 2 чүкө |
| `4` | выбито 5 чүкө |
| `5` | выбито 5 чүкө + ХАН |

Важно: `scenario` определяет только то, что должна показать анимация. Денежный результат определяется значением `win`, полученным от LMS.

## 4. Параметры, которые LMS передаёт при запуске игры

При загрузке игры LMS передаёт стартовые настройки через `X2_LMS_INIT`:

```js
iframe.contentWindow.postMessage({
  type: 'X2_LMS_INIT',
  gameId: 137,
  language: 'RU',
  currency: 'KGS',
  currencyDisplay: 'сом',
  denominations: [15, 30, 50],
  denomination: 15,
  balance: 1255,
  mode: 'real',
  demoAllowed: true,
  demoBalance: 10000
}, '*');
```

### Описание параметров X2_LMS_INIT

| Параметр | Тип | Обязательный | Описание |
|---|---|---:|---|
| `type` | string | да | Тип сообщения. Для инициализации игры всегда `X2_LMS_INIT`. |
| `gameId` | integer/string | да | ID игры в LMS. Игра затем использует это значение в каждом запросе `PayTicket`. |
| `language` | string | да | Язык интерфейса игры. Например `RU`, `KG`. Игрок не меняет язык внутри игры. Все кнопки, подписи и тексты выбираются по этому значению. |
| `currency` | string | да | Код валюты игрового счёта. Например `KGS`, `RUB`. Игрок внутри игры валюту не меняет. |
| `currencyDisplay` | string | рекомендуется | Обозначение валюты, которое показывается возле сумм: например `сом`, `₽`, `$`. Если не передано, игра может показывать значение `currency`. |
| `denominations` | array[number] | да | Список номиналов билетов, доступных игроку в этой игре. Например `[15, 30, 50]`. Именно из этого списка игрок выбирает стоимость следующего билета. |
| `denomination` | number | нет | Номинал, выбранный по умолчанию при первом запуске игры. Передаётся один раз при инициализации. После этого игрок сам меняет номинал внутри игры. LMS не должна повторно присылать этот параметр после каждого выбора. Если параметр не передан, игра выбирает первый элемент из `denominations`. |
| `balance` | number | да | Текущий реальный баланс игрока на момент запуска игры. Используется для первоначального отображения баланса. После каждого реального `PayTicket` баланс обновляется из ответа `PayTicket`. |
| `mode` | string | да | Режим, в котором должна открыться игра: `real` или `demo`. |
| `demoAllowed` | boolean | да | Разрешён ли игроку переключатель REAL/DEMO внутри игры. `true` — можно переключаться, `false` — переключатель скрыт/недоступен. |
| `demoBalance` | number | нет | Стартовый виртуальный баланс DEMO-режима. Используется только в DEMO и не связан с реальным балансом пользователя. Например `10000`. |
| `session` | string | нет | Идентификатор сессии, если LMS решит передавать сессию отдельно. В текущем варианте `PayTicket` предполагается работа через сессию/cookie LMS, поэтому этот параметр не обязателен. |

### Логика номиналов

`denominations` и `denomination` — разные параметры.

Пример:

```js
denominations: [15, 30, 50],
denomination: 15
```

Это означает:

- игроку доступны билеты `15`, `30` и `50`;
- при первом открытии выбран билет `15`;
- игрок может переключить его на `30` или `50`;
- после выбора `30` игра отправляет `amount=30` в `PayTicket`;
- LMS повторно `denomination=30` игре передавать не нужно.

## 5. REAL / DEMO

### `mode`

Допустимые значения:

- `real` — реальная игра;
- `demo` — демонстрационная игра.

В режиме `real` при запуске раунда используется реальный запрос:

```http
Method=PayTicket
```

В режиме `demo` запрос `PayTicket` в LMS не отправляется. Используется виртуальный DEMO-баланс и тестовый результат.

### `demoAllowed`

- `true` — игрок может самостоятельно переключаться между REAL и DEMO;
- `false` — режим определяет LMS, переключателя внутри игры нет.

### `demoBalance`

Виртуальный баланс для DEMO. Например:

```js
demoBalance: 10000
```

Он не должен списываться или начисляться на реальном счёте LMS.

## 6. Баланс

При запуске LMS передаёт:

```js
balance: 1255
```

После реального `PayTicket` LMS возвращает новое значение:

```json
{
  "balance": 1240
}
```

Игра всегда считает значение LMS авторитетным.

Игра не должна самостоятельно делать формулу вида:

```text
старый баланс - ставка + выигрыш
```

для определения реального остатка счёта.

Это важно, поскольку на стороне LMS могут существовать бонусы, комиссии, ограничения или другие правила расчёта.

## 7. Кнопка `+` возле баланса

При нажатии `+` игра не пытается самостоятельно пополнить баланс.

Она отправляет родительской LMS сообщение:

```js
{
  source: 'X2_CHUKO',
  type: 'X2_GAME_DEPOSIT_REQUEST',
  gameId: 137,
  mode: 'real',
  currency: 'KGS',
  denomination: 30,
  language: 'RU',
  balance: 1240
}
```

После этого LMS сама открывает свою страницу, окно или форму пополнения.

### Параметры X2_GAME_DEPOSIT_REQUEST

| Параметр | Тип | Описание |
|---|---|---|
| `source` | string | Источник сообщения. Для этой игры `X2_CHUKO`. |
| `type` | string | Тип события. Для кнопки пополнения `X2_GAME_DEPOSIT_REQUEST`. |
| `gameId` | integer/string | ID игры LMS, из которой пользователь запросил пополнение. |
| `mode` | string | Текущий режим `real` или `demo`. |
| `currency` | string | Валюта счёта игрока. |
| `denomination` | number | Номинал, который в данный момент выбран игроком внутри игры. Это информационное поле, не команда на покупку билета. |
| `language` | string | Текущий язык интерфейса игры. LMS может использовать его для открытия локализованной страницы пополнения. |
| `balance` | number | Последний известный игре баланс пользователя. |

## 8. Основные события игры в сторону LMS

Помимо кнопки пополнения игра может отправлять родительскому окну служебные события.

### `X2_GAME_READY`

Игра загружена и готова получить стартовые данные от LMS.

### `X2_GAME_BALANCE_LOADED`

Игра получила и отобразила баланс.

### `X2_GAME_DENOMINATION_CHANGED`

Игрок изменил выбранный номинал внутри игры.

Пример:

```js
{
  source: 'X2_CHUKO',
  type: 'X2_GAME_DENOMINATION_CHANGED',
  gameId: 137,
  denomination: 30,
  currency: 'KGS',
  language: 'RU'
}
```

LMS может использовать это событие для аналитики, но для работы `PayTicket` оно не обязательно. Реальный выбранный номинал всё равно будет передан как `amount` при покупке билета.

### `X2_GAME_MODE_CHANGED`

Игрок переключил REAL/DEMO, если `demoAllowed=true`.

### `X2_GAME_TICKET_READY`

LMS успешно вернула билет, и игра подготовила соответствующий сценарий к показу.

### `X2_GAME_ERROR`

Игра сообщает родительской LMS об ошибке загрузки, запроса билета, баланса или сессии.

## 9. Тестовые URL-параметры GitHub-сборки

Публичная GitHub-сборка по умолчанию работает в `mock`-режиме, чтобы игру можно было открыть без LMS.

Для интеграционного тестирования могут использоваться параметры URL.

| Параметр | Пример | Назначение |
|---|---|---|
| `mock` | `mock=false` | Выключает локальную эмуляцию и включает работу с LMS. |
| `gameId` | `gameId=137` | Тестовый ID игры LMS. В промышленном запуске его должен передавать LMS. |
| `language` | `language=RU` | Тестовый язык интерфейса. |
| `currency` | `currency=KGS` | Тестовый код валюты. |
| `currencyDisplay` | `currencyDisplay=сом` | Тестовое обозначение валюты. |
| `denominations` | `denominations=15,30,50` | Тестовый список доступных номиналов. |
| `denomination` | `denomination=15` | Первоначально выбранный номинал. |
| `mode` | `mode=real` | Стартовый REAL/DEMO режим. |
| `demoAllowed` | `demoAllowed=true` | Разрешение переключателя REAL/DEMO. |
| `demoBalance` | `demoBalance=10000` | Начальный DEMO-баланс. |
| `balance` | `balance=1255` | Тестовый начальный реальный баланс. |
| `scenario` | `scenario=3` | Принудительный сценарий для локальной/mock-проверки анимации. В реальной игре сценарий возвращает LMS. |

Эти URL-параметры предназначены прежде всего для разработки и тестирования. Для рабочего запуска основные настройки должны поступать от LMS.
