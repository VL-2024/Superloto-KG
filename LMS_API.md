# ЧҮКӨ — обмен игры с LMS (v20)

## 1. Общая схема

В реальном режиме LMS является источником истины для денежных операций и результата билета.

1. LMS запускает игру и один раз передаёт стартовые параметры.
2. Игрок выбирает номинал внутри игры из списка доступных номиналов.
3. При запуске раунда игра вызывает `PayTicket`.
4. LMS списывает стоимость билета, определяет результат и возвращает данные билета.
5. Игра визуализирует результат и показывает баланс, полученный от LMS.

Игра не рассчитывает реальный выигрыш самостоятельно.

---

## 2. Параметры, которые LMS передаёт при запуске игры

При загрузке LMS отправляет игре сообщение `X2_LMS_INIT`.

Пример:

```js
iframe.contentWindow.postMessage({
  type: 'X2_LMS_INIT',
  gameId: 137,
  language: 'RU',
  currency: 'KGS',
  currencyDisplay: 'сом',
  denominations: [25, 50, 100],
  denomination: 50,
  balance: 1255,
  mode: 'real',
  demoAllowed: true,
  demoBalance: 10000
}, '*');
```

### Описание параметров X2_LMS_INIT

| Параметр | Тип | Обязательный | Описание |
|---|---|---:|---|
| `type` | string | да | Тип сообщения. Для инициализации всегда `X2_LMS_INIT`. |
| `gameId` | integer/string | да | ID игры в LMS. Игра использует его в запросе `PayTicket`. Например `137`. |
| `language` | string | да | Язык интерфейса игры, например `RU`, `KG`. Игрок внутри игры язык не меняет. |
| `currency` | string | да | Код валюты, например `KGS`, `RUB`. Игрок внутри игры валюту не меняет. |
| `currencyDisplay` | string | рекомендуется | Обозначение валюты в интерфейсе: `сом`, `₽`, `$` и т. п. |
| `denominations` | array[number] | да | Список номиналов, которые игрок может выбирать внутри игры. Например `[25, 50, 100]`. |
| `denomination` | number | нет | **Номинал, который должен быть выбран по умолчанию при открытии игры.** Передаётся LMS один раз при запуске. Например при `denominations: [25, 50, 100]` и `denomination: 50` игра сразу открывается с выбранным номиналом `50`. После запуска игрок сам может переключиться на `25` или `100`. Если параметр не передан, игра выбирает первый элемент из `denominations`. |
| `balance` | number | да | Текущий реальный баланс игрока на момент запуска. После каждого `PayTicket` обновляется значением из ответа LMS. |
| `mode` | string | да | Режим запуска: `real` или `demo`. |
| `demoAllowed` | boolean | да | Разрешено ли игроку переключаться REAL/DEMO внутри игры. |
| `demoBalance` | number | нет | Начальный виртуальный баланс DEMO-режима. Например `10000`. |
| `session` | string | нет | ID сессии, если LMS решит передавать его отдельно. В текущей схеме допускается работа через cookie LMS. |

### Важно: `denominations`, `denomination` и `amount` — разные параметры

Например LMS запускает игру так:

```js
denominations: [25, 50, 100],
denomination: 50
```

Это означает:

- игроку доступны номиналы `25`, `50`, `100`;
- при открытии игры сразу выбран `50`;
- игрок может поменять его, например, на `100`;
- при покупке следующего билета игра отправит в LMS `amount=100`;
- LMS не должна повторно присылать `denomination=100` после изменения выбора игроком.

`denomination` — только первоначальный выбор при запуске игры.

`amount` — фактически выбранный игроком номинал конкретного покупаемого билета.

## 3. Покупка билета / запуск реального раунда

Формат запроса, переданный разработчиком LMS:

```http
GET https://dev.superloto.kg/api/Lotto.Users.cls?Method=PayTicket&gameId=137&amount=50
```

### Параметры запроса PayTicket

| Параметр | Тип | Обязательный | Кто задаёт | Описание |
|---|---|---:|---|---|
| `Method` | string | да | игра | Для покупки билета всегда `PayTicket`. |
| `gameId` | integer/string | да | LMS | ID игры, полученный игрой при запуске. |
| `amount` | number | да | игрок / игра | Номинал, который игрок выбрал внутри игры для **данного билета**. Например `25`, `50`, `100`. |

Пример: при запуске был выбран по умолчанию `50`, но игрок переключился на `100`:

```http
GET https://dev.superloto.kg/api/Lotto.Users.cls?Method=PayTicket&gameId=137&amount=100
```

## 4. Ответ LMS на PayTicket

Минимальный ответ, необходимый игре:

```json
{
  "ticketId": "123456789",
  "scenario": 3,
  "win": 200,
  "balance": 1240
}
```

### Параметры ответа PayTicket

| Параметр | Тип | Обязательный | Описание |
|---|---|---:|---|
| `ticketId` | string/integer | да | ID/номер созданного билета в LMS. |
| `scenario` | integer | да | Номер визуального сценария результата `1..5`. |
| `win` | number | да | Сумма выигрыша по билету. При проигрыше `0`. |
| `balance` | number | да | Актуальный баланс после операции. Игра показывает именно это значение. |
| `currency` | string | нет | Код валюты. Может возвращаться дополнительно для контроля. |
| `currencyDisplay` | string | нет | Отображаемое обозначение валюты. |
| `multiplier` | number | нет | Множитель выигрыша для отображения. |

**`denomination` из ответа `PayTicket` убран из обязательного контракта**, чтобы не путать его со стартовым параметром `denomination`. Стоимость конкретного билета уже известна игре: это значение `amount`, которое она сама отправила в `PayTicket`.

### Сценарии ЧҮКӨ

| `scenario` | Результат анимации |
|---:|---|
| `1` | ничего не выбито |
| `2` | выбито 1 чүкө |
| `3` | выбито 2 чүкө |
| `4` | выбито 5 чүкө |
| `5` | выбито 5 чүкө + ХАН |

`scenario` задаёт анимацию. Денежный результат определяется полем `win`, полученным от LMS.

## 5. REAL / DEMO

- `mode: 'real'` — реальная игра; используется `PayTicket`.
- `mode: 'demo'` — демонстрационный режим; реальный `PayTicket` не вызывается.
- `demoAllowed: true` — игрок может переключаться REAL/DEMO.
- `demoAllowed: false` — режим задаёт LMS, переключатель внутри игры недоступен.
- `demoBalance` — виртуальный баланс DEMO, не связанный с реальным счётом.

---

## 6. Баланс

При запуске LMS передаёт начальный баланс:

```js
balance: 1255
```

После каждого реального `PayTicket` LMS возвращает новый:

```json
{
  "balance": 1240
}
```

Игра не рассчитывает реальный остаток по формуле `старый баланс - ставка + выигрыш`; авторитетным является баланс LMS.

## 7. Кнопка `+` возле баланса

При нажатии `+` игра отправляет родительской LMS событие:

```js
{
  source: 'X2_CHUKO',
  type: 'X2_GAME_DEPOSIT_REQUEST',
  gameId: 137,
  mode: 'real',
  currency: 'KGS',
  denomination: 100,
  language: 'RU',
  balance: 1240
}
```

Здесь `denomination` означает **текущий выбранный игроком номинал** и является только информационным полем. После события LMS сама открывает страницу/форму пополнения.

## 8. Основные события игры в сторону LMS

### `X2_GAME_READY`
Игра загрузилась и готова получить `X2_LMS_INIT`.

### `X2_GAME_BALANCE_LOADED`
Игра получила и отобразила баланс.

### `X2_GAME_DENOMINATION_CHANGED`
Игрок изменил номинал внутри игры. LMS может использовать событие для аналитики, но оно не обязательно для `PayTicket`.

Пример:

```js
{
  source: 'X2_CHUKO',
  type: 'X2_GAME_DENOMINATION_CHANGED',
  gameId: 137,
  denomination: 100,
  currency: 'KGS',
  language: 'RU'
}
```

При покупке билета это же выбранное значение будет отправлено как `amount=100`.

### `X2_GAME_MODE_CHANGED`
Игрок переключил REAL/DEMO, если это разрешено LMS.

### `X2_GAME_TICKET_READY`
Билет получен от LMS, сценарий подготовлен к отображению.

### `X2_GAME_ERROR`
Сообщение об ошибке игры или интеграции.
